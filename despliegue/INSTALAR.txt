QUE ES ESTE DOCUMENTO
---------------------
Pasos para instalar la version 3.9.1 de Orbith en el servidor SIN conexion a
internet. NO hay ningun script: todos los pasos son ordenes que usted escribe
y revisa una a una. Usted decide en cada momento.

Se mantiene su forma de trabajar: una CARPETA NUEVA para esta version. La
version que funciona hoy NO se toca: queda intacta para volver a ella si hace
falta.

Hasta ahora la instalacion pedia internet para descargar los paquetes de
Python (requirements.txt). Ahora esos paquetes van en la memoria USB y se
instalan desde ella.


QUE TRAE LA MEMORIA USB
-----------------------
  orbith-3.9.1.tar.gz                 Codigo de Orbith 3.9.1 (unos 9 MB).
                                      NO trae el archivo core/.env (claves y
                                      datos de la base): se copia del servidor.
  paquetes-python-linux-py312.tar.gz  Los 67 paquetes de Python para Linux
                                      64 bits y Python 3.12 (unos 65 MB).
                                      Sirve para las proximas versiones
                                      mientras no cambie requirements.txt.
  SHA256SUMS.txt                      Huellas para comprobar que los archivos
                                      llegaron sin danos.
  INSTALAR.txt                        Este documento.


EN LAS ORDENES DE ESTE DOCUMENTO
--------------------------------
  - Lo que esta entre < > lo cambia usted por el valor real de su servidor.
  - Las rutas de ejemplo salen del registro de errores del servidor
    (/home/ebm/orbith, usuario ebm). Cambielas si no coinciden.
  - Ejecute todo como el usuario que corre Orbith (ebm), NO como root, salvo
    lo que usted haga normalmente como administrador (parar y arrancar el
    servicio, Nginx).


===============================================================================
 PARTE A - PREPARAR (Orbith sigue funcionando, no se toca nada en uso)
===============================================================================

A1. Copie los 4 archivos de la memoria a una carpeta del servidor, por ejemplo
    /home/ebm/usb-3.9.1, y compruebe las huellas:

      cd /home/ebm/usb-3.9.1
      sha256sum -c SHA256SUMS.txt

    Las tres lineas deben terminar en "OK" (o "La suma coincide"). Si alguna
    falla, el archivo se dano al copiarlo: vuelva a copiarlo y no siga.

A2. Compruebe el servidor:

      python3 --version     -> debe decir Python 3.12.x
      uname -m              -> debe decir x86_64
      df -h /home/ebm       -> hacen falta unos 600 MB libres

    Si Python NO es 3.12 o la maquina NO es x86_64, NO siga: los paquetes no
    servirian. Avise a Juan para preparar otros.

A3. Anote la carpeta de la version actual (la que usa hoy el servicio). Por
    ejemplo /home/ebm/orbith. En este documento la llamamos ANTERIOR:

      ANTERIOR=</home/ebm/carpeta-de-la-version-actual>
      NUEVA=/home/ebm/orbith-3.9.1
      PAQUETES=/home/ebm/orbith-paquetes-python

A4. Descomprima el codigo y los paquetes:

      tar -xzf /home/ebm/usb-3.9.1/orbith-3.9.1.tar.gz -C /home/ebm
      mkdir -p $PAQUETES
      tar -xzf /home/ebm/usb-3.9.1/paquetes-python-linux-py312.tar.gz -C $PAQUETES

    Resultado: la carpeta /home/ebm/orbith-3.9.1 y, dentro de $PAQUETES,
    los 67 archivos .whl.

A5. Copie la configuracion (claves y conexion a la base) de la version actual:

      cp $ANTERIOR/core/.env $NUEVA/core/.env

A6. Fotos de los usuarios y registro de errores. Mire si el .env los guarda
    fuera de la carpeta de la version:

      grep -E "MEDIA_DIR|LOG_DIR" $NUEVA/core/.env

    - Si aparece MEDIA_DIR: las fotos ya estan fuera y no hay que hacer nada.
    - Si NO aparece: copie la carpeta de fotos a la version nueva:
        cp -a $ANTERIOR/media $NUEVA/
    - Igual con LOG_DIR y la carpeta logs (si no aparece, no hace falta copiar
      nada: la version nueva crea su propia carpeta logs).

A7. Cree el entorno de Python de la version nueva e instale los paquetes
    DESDE LA CARPETA, sin internet:

      cd $NUEVA
      python3 -m venv venv
      venv/bin/pip install --no-index --find-links=$PAQUETES -r requirements.txt

    "--no-index" hace que pip NO intente conectarse a internet.
    Debe terminar con "Successfully installed ...". Si dice que no encuentra
    un paquete, NO siga y avise a Juan con el mensaje exacto.

    IMPORTANTE: un entorno de Python (venv) NO se puede mover ni renombrar de
    carpeta despues de crearlo. Por eso se crea ya en su carpeta definitiva.

A8. Compruebe la version nueva SIN tocar la base de datos:

      venv/bin/python manage.py check
        -> debe decir "System check identified no issues"

      venv/bin/python manage.py showmigrations | grep "\[ \]"
        -> lista los cambios de la base que faltan por aplicar. Compare con
           la PARTE E de este documento. Ninguna linea = la base ya esta al dia.

A9. Prepare los archivos estaticos (estilos, imagenes, JavaScript) en la
    carpeta nueva. No afecta a la version en uso:

      venv/bin/python manage.py collectstatic --noinput

Hasta aqui NADA ha cambiado en el Orbith que se esta usando.


===============================================================================
 PARTE B - ACTUALIZAR (con Orbith detenido; calcule unos 15 minutos)
===============================================================================

Avise a los usuarios de que Orbith estara detenido unos minutos.

B1. Detenga el servicio de Orbith como lo hace normalmente
    (por ejemplo: sudo systemctl stop <nombre-del-servicio>).

B2. Haga una COPIA DE LA BASE DE DATOS. Los datos de conexion estan en el .env:

      grep -E "DATABASE_(NAME|USER|HOST|PORT)" $NUEVA/core/.env

      mkdir -p /home/ebm/orbith-respaldos
      pg_dump -Fc -h <HOST> -p <PUERTO> -U <USUARIO> -d <NOMBRE_BASE> \
              -f /home/ebm/orbith-respaldos/orbith_antes_3.9.1_$(date +%Y%m%d_%H%M).dump

    Pedira la contrasena de la base (DATABASE_PASSWORD del .env).
    Compruebe que la copia es legible:

      pg_restore -l /home/ebm/orbith-respaldos/orbith_antes_3.9.1_*.dump | head

    Debe mostrar unas lineas que empiezan por ";". Si da error, NO siga:
    arranque de nuevo el servicio (version anterior) y avise a Juan.

B3. Aplique los cambios de la base de datos:

      cd $NUEVA
      venv/bin/python manage.py migrate --noinput

    Debe terminar sin errores ("Applying ... OK" en cada linea).
    -> Si da un ERROR: vaya a la PARTE C. NO arranque la version nueva.

B4. Compruebe que no queda nada pendiente:

      venv/bin/python manage.py showmigrations | grep "\[ \]"
        -> no debe mostrar ninguna linea.

B5. Haga que el servicio use la carpeta nueva. Es el paso que usted hace
    siempre al cambiar de version: en la configuracion del servicio, cambie
    la ruta de la carpeta anterior por la nueva ($NUEVA), tanto la carpeta de
    trabajo como la del programa (venv/bin/gunicorn). Si Nginx sirve /static/
    o /media/ desde la carpeta anterior, cambie tambien esas rutas.

B6. Arranque el servicio (por ejemplo: sudo systemctl start <nombre-del-servicio>).

B7. Compruebe en el navegador:
    - Orbith abre y deja entrar.
    - Menu del usuario -> "Acerca de Orbith": debe decir version 3.9.1.
    - Abra la Lista de Contratos y el Gestor de Plantilla: deben cargar.
    Si algo falla, mire el registro de errores (carpeta logs o LOG_DIR, archivo
    del dia) y envieselo a Juan.


===============================================================================
 PARTE C - SI FALLA EL "migrate" DEL PASO B3
===============================================================================

NO arranque la version nueva. Copie el mensaje de error completo para Juan.

Cada cambio de la base se aplica entero o no se aplica, pero los cambios
anteriores al que fallo SI quedaron aplicados. Por eso lo seguro es devolver
la base exactamente a como estaba, con la copia del paso B2. Decida usted:

  1) Devolver la base a como estaba (recomendado):

       pg_restore --clean --if-exists --no-owner \
                  -h <HOST> -p <PUERTO> -U <USUARIO> -d <NOMBRE_BASE> \
                  /home/ebm/orbith-respaldos/orbith_antes_3.9.1_<FECHA>.dump

     Despues arranque el servicio SIN cambiar nada de su configuracion: sigue
     apuntando a la carpeta anterior, que esta intacta.

  2) Dejar la base como quedo y esperar instrucciones de Juan (Orbith sigue
     detenido mientras tanto).

Estas ordenes de copia (B2) y restauracion se probaron en PostgreSQL 17 sobre
una copia de la base de pruebas.


===============================================================================
 PARTE D - VOLVER A LA VERSION ANTERIOR DESPUES (si aparece un problema grave)
===============================================================================

  1. Detenga el servicio.
  2. Devuelva la base a como estaba (la orden de la PARTE C, opcion 1).
     ATENCION: se pierde todo lo que se haya registrado en Orbith despues de
     la actualizacion.
  3. Vuelva a poner en el servicio (y en Nginx) la ruta de la carpeta anterior.
  4. Arranque el servicio.

No se borra nada: la carpeta anterior, la nueva y las copias de la base se
conservan todas.
